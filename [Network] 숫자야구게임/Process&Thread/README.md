🔎 Process와 Thread의 생성부터 종료까지의 시간을 비교하는 간단한 미니 프로젝트를 진행해봤습니다.

일반적으로 thread는 process보다 가볍다고 알려져 있습니다. 하지만 실제 측정에서는 예상과 다른 결과가 나타났고, 그 이유를 확인해 보고자 직접 비교해 보았습니다.

이번 프로젝트에서는 fork()와 pthread_create()을 사용해 실행 단위를 1개부터 20개까지 늘려가며 시간을 측정했습니다.
```
🖥 실행 환경
- CPU(s): 2
- Thread(s) per core: 1
```

프로젝트를 통해 확인한 점은 크게 세 가지였습니다.

1) 실행 단위가 1개일 때는 process와 thread의 실행 시간이 거의 비슷하게 측정되었습니다. 단일 스레드 프로세스 기준에서는 실행 흐름이 1개라는 점에서 유사하게 보일 수 있었습니다.

2) 사용 가능한 CPU가 2개인 환경이기 때문에 실행 단위가 3개 이상이 되면 CPU 경합이 발생할 수 있다고 보았습니다. 실제 측정 결과에서도 일부 구간에서는 실행 시간이 눈에 띄게 증가하는 모습을 확인할 수 있었습니다.

3) 후반부로 갈수록 thread 실행 시간이 process보다 더 크게 측정되는 구간이 나타났습니다. 일반적으로 thread가 process보다 가볍다고 알려져 있지만, 이번 실험에서는 스레드 함수가 즉시 종료되는 구조였기 때문에 실제 작업 시간보다는 생성, 종료, 회수 과정의 오버헤드가 더 크게 반영된 것으로 해석했습니다.

💡이번 프로젝트를 통해 단순히 “thread가 process보다 항상 빠르다”라고 볼 수는 없다는 점을 다시 느꼈습니다. 실행 환경과 측정 방식에 따라 결과가 달라질 수 있고, 특히 운영체제의 CPU 개수와 스케줄링의 영향이 크게 작용했습니다. 또한 단순한 생성, 종료 오버헤드가 아닌 실제 연산이 필요한 작업을 넣는다면 결과가 달라질 수 있다는 점도 흥미로웠습니다.
